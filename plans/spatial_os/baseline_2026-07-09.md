# Spatial OS Execution Baseline - 2026-07-09

Captured before Wave B implementation. This is evidence for regression
comparison, not a claim that the current runtime is healthy.

## Live processes and listeners

- Canonical runtime: DS8, `--pgie-profile yolo26 --size m`.
- DS8 uptime at final baseline capture: 34,261 seconds.
- DS8 process load: approximately 104% CPU and 2.2 GiB RSS.
- GPU: driver 580.167.08, approximately 81% utilization and 3.8/12.3 GiB
  memory in use at the sample instant.
- LAN listeners:
  - Noesis RTSP `8554`, WebSocket `6008`, REST `8080`;
  - Menon server `3001` and Vite `5175`;
  - Noesis operator Vite `5173`.
- No DS9 runtime was active.

The live DS8 process predates some working-tree edits. Runtime evidence and
current source evidence must therefore remain explicitly distinguished.

## SDK and application environment

- Python 3.12.3.
- DeepStream 8.0.
- CUDA driver/runtime family 13.0.
- TensorRT Python 10.13.3.9.
- Default shell Node 18.19.1; required Menon build runtime Node 22.22.0.
- DS9 requires a separate DS9 environment and complete DS9-native artifacts;
  the current host is not a DS9 validation environment.

## Working-tree ownership boundary

Noesis began Wave B with 46 modified tracked files plus untracked identity UI,
developer-console, script, and test work. The main dirty groups are:

- household identity/provisional-pool/enrollment UI;
- developer-console launch/configuration work;
- V3DT configuration and hook parity;
- BEV trail/render changes;
- generated operator build output.

Menon began Wave B with 11 modified tracked files plus untracked planning/test
work. The main dirty groups are reconstruction rendering, tracking/trail
visuals, settings, authored-environment loading, and generated runtime/build
output.

Existing changes are user-owned and are preserved. Each execution checkpoint
must stage explicit files only.

## Test baseline

- Focused Noesis spatial suite: 82 passed.
- Household/StableID selection: 76 passed, 2 failed:
  - aliased/reserved IDs could be returned to the free pool;
  - an active copresence guard did not prevent one auto-merge.
- Full Noesis collection: 443 tests discovered, then collection stopped because
  `test_dewarper_validity_mask.py` imports a helper absent after the DS9 rollback.
- Menon: 41 tests passed.
- Menon Node 22 type check and production build: passed, with existing bundle
  size and mixed dynamic/static import warnings.
- Agent/docs consistency: passed.
- Both worktrees passed whitespace checks.

## Identity-health baseline

The live endpoint reported, at the final sample:

- 73,209 new SID allocations;
- 66,550 fragmentation events;
- 67,914 provisional events;
- 2,561 visitor mints;
- 36,788 false-share blocks / overlap denials;
- zero overlap grants;
- 28,698 gallery-quality rejects;
- six resident records and two visitor identities.

Two resident display names normalize to duplicates. The endpoint currently
reports resident gallery counts, but the identity audit found those counts can
be stale relative to persistence; Wave B must make health derive from store
truth before these numbers are used as acceptance evidence.

## Security baseline

- All listed services were reachable on all interfaces.
- Noesis REST/WS and Menon mutations had no authenticated appliance boundary.
- Menon allowed wildcard CORS.
- A page-load GET could regenerate the HomeSeer catalog and accepted caller
  backend/credential/output parameters.
- The agent process inherited the server environment and relied primarily on
  prompt policy for mutation safety.
- Household identity state used group-readable/group-writable modes and had no
  bounded biometric backup retention.

## Baseline interpretation

The working GPU/media path is valuable and must be preserved. Identity health,
security, test discovery, DS8/DS9 ownership, and product contract truth are not
release-ready and form the first implementation gates.
